# Cost Slicer — G-code Import, UX Refresh, and SEO

**Date:** 2026-04-27
**Status:** Approved (brainstorming phase)
**Scope:** Single implementation cycle.

## 1. Goal

Turn Cost Slicer from a manual-entry calculator into a drop-and-go tool: the user drags a G-code file from their slicer, the app reads print time, filament weight, filament type, and printer model from header comments, and pre-fills the form. Manual entry remains as the fallback. While at it, refresh the visual design, persist user settings, and make the app discoverable via search engines and social shares.

Non-goals (explicit): `.3mf` parsing, job history, accounts, i18n, backend.

## 2. Architecture

Client-side only. Static SPA, deployed to Vercel as today.

New modules:

- `src/gcode/gcodeParser.ts` — pure function `parseGcode(text: string): ParsedJob | ParseError`. Reads the first 300 lines and last 300 lines of the file (slicer metadata lives in headers/footers; ignoring the body keeps parse time bounded for large files).
- `src/gcode/slicerProfiles.ts` — registry of slicer detectors and field extractors. One profile per slicer flavor (PrusaSlicer, SuperSlicer, OrcaSlicer, BambuStudio, Cura).
- `src/gcode/types.ts` — `ParsedJob`, `ParseError`, `SlicerFlavor`, `RawMetadata`.
- `src/components/FileDropZone.tsx` — drag-drop + click-to-browse area.
- `src/components/ResultCard.tsx` — replaces the inline table.
- `src/components/SettingsCard.tsx` — collapsible cost-settings group.
- `src/lib/persistence.ts` — typed `localStorage` wrapper for settings.

Modified:

- `src/App.tsx` — restructured into hero / dropzone / job inputs / settings card / result card. Uses `useReducer` for form state instead of seven `useState` strings.
- `public/index.html` — SEO meta tags, OG, JSON-LD, favicon.
- `src/theme.ts` — brand palette + typography refinements.

Removed:

- `src/PrinterSelector.tsx` and unused `printerMatrix.ts` exports — superseded by parser-detected printer (kept as an internal fallback table for printers we recognize but whose power isn't in the file; see §3.4).

### 2.1 Data flow

```
file drop
  → FileReader.readAsText
  → parseGcode(text)
    → detectFlavor(text) → SlicerFlavor | "unknown"
    → flavor.extract(text) → RawMetadata
    → normalize(RawMetadata) → ParsedJob
  → dispatch({type: "import", payload: ParsedJob})
  → form fields populated, "Imported from <flavor>" chip shown
  → user reviews/edits → clicks "Slice Costs"
  → calculatePrintCost(...) → ResultCard
```

Form state shape:

```ts
type FormState = {
  printTime: { hours: number; minutes: number };
  filamentWeight: string;       // grams
  filamentType: string | null;  // display only, e.g. "PLA"
  printerModel: string | null;  // display only
  electricityCost: string;      // currency / kWh
  printerPower: string;         // kW
  filamentCost: string;         // currency / kg
  currency: "PLN" | "USD" | "EUR";
  showDepreciation: boolean;
  printerCost: string;
  printerLifespan: string;      // years
  importSource: SlicerFlavor | null;
};
```

Persistence: only the "settings" subset (`electricityCost`, `printerPower`, `filamentCost`, `currency`, `showDepreciation`, `printerCost`, `printerLifespan`) is saved to `localStorage` under key `cost-slicer:settings:v1`. Job-specific fields are not persisted.

## 3. G-code parser

### 3.1 Flavor detection

Detect by signature comment in the first 300 lines, in this order (most specific first):

| Flavor | Signature regex |
| --- | --- |
| BambuStudio | `/^; HEADER_BLOCK_START/m` or `/^; generated by BambuStudio/im` |
| OrcaSlicer | `/^; generated by OrcaSlicer/im` |
| SuperSlicer | `/^; generated by SuperSlicer/im` |
| PrusaSlicer | `/^; generated by PrusaSlicer/im` |
| Cura | `/^;Generated with Cura_SteamEngine/m` or `/^;FLAVOR:/m` |

If none match → `"unknown"` → `ParseError("unsupported_slicer")`.

### 3.2 Field extraction per flavor

For each flavor, extract: `estimatedTimeSeconds`, `filamentWeightGrams`, `filamentType`, `printerModel`. Each field is independently optional; missing fields stay `null` and the user fills them manually.

**PrusaSlicer / SuperSlicer / OrcaSlicer** (shared comment vocabulary):

- Time: `; estimated printing time (normal mode) = 1h 23m 45s` — parse `(\d+)d` `(\d+)h` `(\d+)m` `(\d+)s` pieces.
- Weight: `; filament used [g] = 12.34` (sum if multiple).
- Type: `; filament_type = PLA` (first value if comma-separated).
- Printer: `; printer_model = MK4IS` → display name lookup, fallback to raw value.

**BambuStudio**:

- Time: `; total estimated time: 1h 23m 45s`
- Weight: `; total filament weight [g]: 12.34`
- Type: `; filament_settings_id = "Bambu PLA Basic"` → strip vendor prefix.
- Printer: `; printer_model = Bambu Lab X1 Carbon`

**Cura**:

- Time: `;TIME:4567` (seconds).
- Weight: not directly emitted. Parse `;Filament used: 1.234m` plus `;Filament cost:` if present. If only length is available, attempt density estimate using filament type and standard 1.75 mm cross-section (PLA 1.24 g/cm³, PETG 1.27, ABS 1.04, default 1.24); flag the result as estimated in the UI ("≈ 12.3 g — verify").
- Type: `;Filament type:` if present, else `null`.
- Printer: `;TARGET_MACHINE.NAME:Ender 3` if present.

### 3.3 Normalization

```ts
type ParsedJob = {
  flavor: SlicerFlavor;
  printTime: { hours: number; minutes: number } | null;
  filamentWeightGrams: number | null;
  filamentWeightEstimated: boolean;
  filamentType: string | null;
  printerModel: string | null;
};
```

Round print time down to the nearest minute (calculator works in minutes).

### 3.4 Printer power lookup

After import, if `printerModel` matches an entry in `printerMatrix.ts`, suggest the average power (filtered by `filamentType` if known, else `Default`) by pre-filling `printerPower`. The user can override. The matrix is kept and extended as fallback data — no UI selector.

### 3.5 Errors

`ParseError` discriminated union: `"unsupported_slicer"`, `"empty_file"`, `"too_large"` (>50 MB hard cap), `"read_failed"`. UI surfaces a friendly message and keeps manual entry available.

## 4. UX refresh

### 4.1 Layout

Single-column, max-width `md` (was `sm`), responsive padding. Top to bottom:

1. **Hero** — app title (h1, brand accent), one-line tagline, no other chrome.
2. **Drop zone card** — large dashed-border area, "Drop a `.gcode` file or click to browse", supported-slicers line below. After import: collapses into a compact summary row ("Imported from PrusaSlicer · MK4 · 47 g PLA · 1h 23m") with an "Import another" link.
3. **Job inputs card** — print time + filament weight. Pre-filled from import; editable.
4. **Settings card** — collapsible. Currency, electricity cost, printer power, filament cost, depreciation toggle + its two fields. Collapsed by default once persisted settings exist; expanded on first visit.
5. **Slice Costs button** — primary, full-width on mobile.
6. **Result card** — shown after calculation: large total in currency at top, three stat tiles (Electricity / Filament / Depreciation), per-gram and per-hour breakdown line, "Copy summary" button.
7. **Footer** — "Made in Poland with ❤️" and a "Suggestions & issues" link to `https://github.com/tdi/cost-slicer/issues` (`target="_blank"`, `rel="noopener noreferrer"`).

### 4.2 Visual / theme

- Single primary accent (warm orange `#E4572E` or similar — to be finalized in implementation; keep it tokenized in `theme.ts`).
- Typography: keep Roboto, but title uses display weight; field labels use MUI floating labels (drop the inline `subtitle1` headings).
- Cards: `Paper` with `elevation={1}`, rounded corners (`borderRadius: 12`), generous padding.
- Dark mode: keep `prefers-color-scheme` reactivity; verify accent contrast in both modes.
- Favicon and `apple-touch-icon` swapped from CRA default to a Cost Slicer mark.

### 4.3 Heading hierarchy

Exactly one `<h1>` ("Cost Slicer"). Section titles become `<h2>`. The current "3D Print Cost Calculator" line becomes a `<p>` tagline.

### 4.4 Persistence behavior

On mount, `useEffect` reads `cost-slicer:settings:v1` and dispatches `{type: "hydrate", payload}`. On every settings field change, debounced (300 ms) write back. Versioned key allows future schema changes.

### 4.5 Mobile

- Dropzone shows "Tap to choose a file" instead of drag instructions on touch (`pointer: coarse` media query).
- Stat tiles in result card stack vertically below `sm` breakpoint.
- Bottom-safe-area padding for iOS.

## 7. Component contracts

### `parseGcode(text: string): ParsedJob | ParseError`

- Pure. No I/O. No throws — errors as values.
- Time complexity O(n) on file length but bounded: only first 300 + last 300 lines are scanned.
- Determinism: same input → same output.

### `<FileDropZone onImport onError disabled />`

- Owns its own hover/drag-over visual state.
- Calls `onImport(ParsedJob)` on success, `onError(ParseError)` on failure.
- Does not own form state.

### `<SettingsCard value onChange currency />`

- Controlled. Parent owns settings state.
- Renders the entire settings group as a single collapsible card.

### `<ResultCard costs currency />`

- Pure presentational.
- Receives a `CostBreakdown` and renders the result UI.

### `lib/persistence.ts`

- `loadSettings(): Partial<Settings> | null`
- `saveSettings(s: Settings): void` (debounced by caller)
- Fails silently on quota / disabled storage; never throws.

## 9. Risks and open questions

- **Cura weight estimation accuracy** — density-based estimate can be off by a few percent. Mitigation: clearly flag as estimated and let the user override.
- **Slicer comment drift** — slicer vendors change comment formats between versions. Mitigation: profiles are isolated and easy to add patterns to; tests pin behavior.
- **Final brand accent color and OG image** — to be picked during implementation; not a blocker for the spec.
- **Production canonical URL** — confirm before shipping (placeholder `cost-slicer.vercel.app`).
